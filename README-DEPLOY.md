# مركز المهندس الشامل — Render Free + Neon ومخزون خاص بالإدارة

## الحل المجاني وحدوده

المتجر ولوحة التحكم وصفحة QR يفضلوا على **خدمة Render Free الحالية** بنفس عنوان `https://elmohandes.onrender.com`، والبيانات تتحفظ في **Neon PostgreSQL Free** خارج Render. قاعدة البيانات تحفظ المنتجات والأسعار والمخزون والصور المرفوعة وطلبات الشراء والصيانة وسجل الزوار وإعدادات صفحة التواصل. الخدمة لا تكتب قاعدة بديلة على مساحة Render المؤقتة.

- **لو لازم البيانات نفسها تكون داخل Render:** مفيش تخزين دائم مجاني مناسب. الخدمة المجانية لا تدعم Persistent Disk، وRender Postgres المجاني ينتهي بعد ٣٠ يومًا، وRender Key Value المجاني يفقد البيانات عند إعادة تشغيله. [توثيق Render Free](https://render.com/docs/free)
- **Neon Free ليست تجربة ٣٠ يومًا.** راجع [الحدود الرسمية الحالية](https://neon.com/docs/introduction/plans)؛ وقت إعداد النسخة: ١ جيجابايت لقاعدة البيانات لكل مشروع، و١٠٠ ساعة حوسبة CU شهريًا لكل مشروع، و٥ جيجابايت نقل عام. الصور المرفوعة هنا ضمن سعة قاعدة البيانات، فتابع الاستخدام في Neon. وضع السكون قد يؤخّر أول زيارة، لكنه لا يمسح السجلات. اقفل لوحة التحكم لما تخلص، لأن التحديث التلقائي في التبويب المفتوح يستهلك الحصة. [أسعار Neon](https://neon.com/pricing)

## ١. خُد نسخة من الموقع الحالي قبل التغيير

1. افتح [لوحة التحكم الحالية](https://elmohandes.onrender.com/admin) ← **الإعدادات ← تصدير نسخة كاملة**. احفظ الملف في مكان خاص (فيه بيانات عملاء وزوار)، ولا ترفعه إلى GitHub. لو فيه طلبات بتوصل باستمرار، صدّر آخر نسخة مباشرةً قبل التحويل، والأفضل ما تستقبلش طلبات أثناء النقل القصير.
2. لو النسخة القديمة فيها **مسارات الصور بس**، نزّل ملفات الصور من الموقع قبل إعادة النشر. من مجلد المشروع افتح الطرفية بـ Node.js 22 وشغّل الآتي، مع استبدال اسمي الملفين بمكان ملفك واسم الملف الجديد:

   ```bash
   node tools/bundle-old-uploads.js old-backup.json backup-with-images.json
   ```

   الأداة تحفظ الصور المشار إليها تحت `/uploads/` إذا كانت لا تزال موجودة على الموقع. لو صورة مفقودة، ارفع الأصل من محرّر المنتج بعد التحويل. الصور المرفقة بكود المشروع لا تحتاج تنزيلًا منفصلًا. لا يمكن استرجاع بيانات اتحذفت قبل أخذ النسخة.
3. لو كنت قد فعّلت قرص Render دائم بالفعل، **ما تفصلوش أو تمسحه قبل التأكد إن النسخة والبيانات والصور اتنقلت بنجاح**. لو الخدمة مدفوعة حاليًا، ممكن تتأكد من Neon أولًا على نفس الخدمة ثم تنقلها لخطة Free بعد تأمين النسخ. لو الخدمة مجانية أصلًا، مفيش قرص مطلوب.

## ٢. أنشئ قاعدة Neon المجانية واربطها بـ Render الحالية

1. افتح [Neon](https://console.neon.tech/signup)، واختار **Free**، ثم اعمل مشروع جديد باسم تختاره. يفضّل اختيار منطقة قريبة من منطقة خدمة Render لتقليل تأخير الاتصال.
2. من المشروع اضغط **Connect**. اختار قاعدة المشروع (عادةً `neondb`) والدور المالك الذي يقدر ينشئ الجداول. اختار **Direct connection** (أوقف Connection pooling في نافذة النسخ إن كان مفعّلًا)، وانسخ رابط PostgreSQL بالكامل. الرابط يحتوي الاسم وكلمة المرور؛ حطّه في **Render → Environment** فقط، مش في الكود أو GitHub أو المحادثة. التطبيق يفرض اتصال TLS بتحقق من الشهادة واسم الخادم.
3. على Render افتح **خدمة ElMohandes الحالية**، مش `New Web Service`، عشان تحافظ على الرابط الحالي والـQR. أوقف Auto-Deploy مؤقتًا لو لزم، وارفع ملفات الإصدار الجديد إلى مستودع الخدمة الحالي، ثم اضبط:

   | المكان | الإعداد | القيمة |
   |---|---|---|
   | Settings | Instance Type | `Free` عند اكتمال النسخ من أي قرص قديم |
   | Settings | Runtime | `Node` |
   | Settings | Build Command | `npm ci --omit=dev` |
   | Settings | Start Command | `npm start` |
   | Settings | Health Check Path | `/api/health` |
   | Environment | `NODE_VERSION` | `22` |
   | Environment | `DATABASE_URL` | النص الذي نسخته من Neon |
   | Environment | `REQUIRE_POSTGRES` | `1` |
   | Environment | `ADMIN_PASSWORD` | كلمة مرور جديدة قوية، ١٢ حرفًا على الأقل، تُستخدم عند تهيئة القاعدة لأول مرة |
   | Environment | `SEED_DEMO` | `0` |
   | Environment | `SEED_CATALOG` | `0` لو هتستورد كتالوجك من نسخة؛ احذفه لو عايز المنتجات التسعة المرفقة على قاعدة جديدة |

   لا تحتاج `DATA_DIR` أو `DATABASE_PATH` أو `PERSISTENT_DISK_PATH` على Free. ملف `render.yaml` فيه نفس إعدادات النشر؛ للخدمة المنشأة يدويًا ظبّط القيم في لوحتها. لا تنشئ قاعدة Render Postgres مجانية لهذا المسار.
4. شغّل **Manual Deploy → Deploy latest commit**. التطبيق ينشئ الجداول تلقائيًا على قاعدة Neon. لو `DATABASE_URL` ناقص أو الاتصال فشل عند التشغيل، راجع Render Logs؛ النسخة ترفض بدء قاعدة مؤقتة بدل ما تعرض لك كتالوج فاضي على أنه بياناتك.
5. افتح `/admin` بكلمة المرور التي ضبطتها للقاعدة الجديدة. تحقق من **الإعدادات ← حالة النظام**: القيمة المطلوبة **«PostgreSQL — تخزين دائم خارجي»**. من **النسخ الاحتياطي والاستيراد** استورد نسخة JSON المحفوظة لو عندك. راجع عدد المنتجات، الصور والطلبات، ثم سجّل كمية لمنتج تجريبي وأعد تشغيل خدمة Render. اتأكد إن القيمة والصورة فضلوا موجودين. افتح كمان `/qr`؛ رابط الطباعة ما اتغيّرش.

## ٣. استخدام المخزون الخاص بالإدارة

- **لوحة التحكم ← المنتجات ← تعديل** منتج، أو **منتج جديد**. في خانة **الكمية في المخزون** اكتب عدد الوحدات واضغط حفظ. الخانة الفاضية تعني **غير محدد**، والصفر يعني **نفد**. تقدر تدخل أرقام عربية أو إنجليزية، والحد ٠ إلى ٩٩٩٩٩٩.
- أعلى المنتجات فيه أربع حالات قابلة للفلترة: **متوفر** (٤ قطع أو أكثر)، **منخفض** (١–٣)، **نفد** (صفر)، و**غير محدد**. الكمية تظهر في كارت المنتج داخل اللوحة.
- المخزون **يدوي وللإدارة فقط**؛ لا يظهر في داتا الكتالوج العام حتى لو طلبها المستخدم مباشرة. صفر المخزون لا يخفي المنتج ولا يمنع العميل من إرسال طلب، والطلب لا يخصم الكمية تلقائيًا.
- نسختا **المنتجات** و**النسخة الكاملة** تتضمنان المخزون والصور المرفوعة المتاحة. الاستيراد يدمج السجلات دون مسح الموجود؛ لو المنتج مطابق، يملأ الكمية غير المحددة فقط ولا يكتب فوق كمية موجودة. للاستعادة على قاعدة فاضية، اضبط `SEED_CATALOG=0` قبل أول تشغيل.

## ٤. صفحة التواصل والنسخ الاحتياطي

- **الإعدادات ← صفحة التواصل ورمز QR** لتعديل الاسم والوصف والواتساب والروابط. الصفحة على `/qr`، والرمز السابق يظل صالحًا ما دام الدومين والمسار ثابتين. ملفات الكود تحت `public/assets/elmohandes-qr.png` و`public/assets/elmohandes-qr.svg`.
- احفظ نسخة JSON بشكل دوري خارج الاستضافة. النسخة الكاملة تشمل الطلبات والزوار وIP وإعدادات التواصل، ولا تشمل كلمة مرور المدير. لا تشاركها. حد ملف لوحة التحكم ٣٢ ميجابايت؛ لو تعدّاه، خذ نسخة PostgreSQL مباشرةً بـ `pg_dump` من جهاز موثوق (استخدم إصدار عميل لا يقلّ عن إصدار الخادم). استخدم رابط الاتصال المباشر من متغيّر بيئة محلي:

  ```bash
  pg_dump --format=custom --no-owner --no-privileges --file=mohandis-backup.dump "$DATABASE_URL"
  ```

  نسخة قاعدة البيانات المباشرة تتضمن بيانات حسّاسة منها تجزئة كلمة المرور ومفتاح الجلسات؛ احفظها بشكل آمن. لا تستورد نسخة قاعدة خام فوق قاعدة حية من غير إجراءات استعادة منفصلة. لو مصدر النقل SQLite على قرص، احتفظ بنسخة SQLite متسقة (`sqlite3 … '.backup …'`) وبمجلد الصور القديم أيضًا.

## تشغيل واختبار محلي

```bash
npm ci
npm start   # http://localhost:3000/admin — SQLite للتجربة لو DATABASE_URL غير مضبوط
npm test    # اختبارات التخزين وصلاحيات المخزون وQR
```

للتجربة المحلية فقط، كلمة المرور الافتراضية `admin12345`. عند استخدام `TEST_POSTGRES_URL` في الاختبار، مرّر رابط PostgreSQL **محلي وتجريبي فقط** لدور يمكنه إنشاء قواعد اختبار عشوائية وحذفها. اختبارات المتصفح تحتاج Playwright (`npm install --no-save playwright` ثم `npx playwright install chromium`) وخادمًا محليًا بقاعدة جديدة و`SEED_DEMO=1`؛ شغّل `npm run test:e2e`. لا تستخدم أيًّا من اختبارات التعديل على بيانات العمل. نجحت ٧ اختبارات للخادم (تشمل PostgreSQL محليًا وإعادة تشغيل التطبيق بمسار تخزين جديد)، و٣٨ تحققًا في Chromium على PostgreSQL. لم يُختبر الاتصال بحساب Render أو Neon الخاص بك قبل ربطه.

الخيار القديم للقرص الدائم ما زال مدعومًا لو أردته في خطة Render مدفوعة أو Docker: عدم ضبط `DATABASE_URL` أو `REQUIRE_POSTGRES`، وتعيين `DATA_DIR` و`PERSISTENT_DISK_PATH` إلى مسار القرص المتصل. هذا ليس مسار Render Free.
